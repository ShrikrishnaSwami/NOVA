# NOVA task scheduler

NOVA includes a persistent local scheduler. Jobs and their execution history are stored in the local SQLite database used by the application. The scheduler starts with the local API service and stops with it.

## Current scheduled actions

The current registered scheduled handlers are read-only:

- `system.snapshot`: collect CPU, memory, and platform status.
- `storage.report`: collect disk capacity and free-space information.

These handlers report information; they do not change system settings or modify files.

## Approval and recurrence

A new task starts in `pending_approval`. It does not execute until the user approves that exact task. Supported recurrence options are:

- `once`
- `daily`
- `weekly`

Approved tasks can be paused or cancelled. Each execution is recorded in local history. A failed execution is marked as failed rather than silently retried. If NOVA notifications are enabled, the desktop can report task outcomes through native Windows notifications.

## API

- `GET /tasks/capabilities` — registered task actions and recurrence options.
- `POST /tasks` — create a task with a timezone-aware future `schedule_at`.
- `GET /tasks` — list tasks; supports status and limit filters.
- `POST /tasks/{id}/approve` — approve the selected task.
- `POST /tasks/{id}/pause` — pause a task.
- `POST /tasks/{id}/cancel` — cancel a task.
- `GET /tasks/{id}/history` — inspect execution records.

Example request:

```json
{
  "title": "Daily system snapshot",
  "action_id": "system.snapshot",
  "parameters": {},
  "schedule_at": "2030-01-01T09:00:00-05:00",
  "recurrence": "daily"
}
```

Use a real future date/time with the correct timezone for your location.

## Notifications

Task completion and failure notifications are optional and depend on NOVA's notification preference and Windows notification settings. Notifications are generated by NOVA itself. NOVA does not read the contents of notifications from other applications.

## Security boundary

The scheduler does not execute arbitrary commands, scripts, model-generated code, or arbitrary filesystem operations. Only handlers registered in the task registry can run. The current handlers are read-only reports.

Software installation, Windows Update, deletion, registry changes, shutdown/restart, and other mutating operations are not schedulable actions in the current implementation. They would require separate typed implementations, scoped permissions, and explicit approval UX before being added.

The scheduler is intended for a local desktop user and a loopback-bound API. It is not a hardened multi-user scheduling service.
